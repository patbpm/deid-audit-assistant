# Synthetic note dataset

Status: Day 2 build, in progress. The set is not frozen yet; the plan freezes the test set after Day 3.

All text is generated by code in `deid/synth/`. No real patient data, and nothing from any research project, is used. Names, places and numbers are invented combinations; phones, SSNs and emails are drawn from ranges that are reserved or never issued.

## Reproduce

```powershell
python -m deid.synth.generate            # defaults: seed 20261027, 150 patients
python -m unittest discover -s tests -t .
```

Output goes to `data/generated/` (git-ignored): `notes.jsonl` and `manifest.json`. The same seed gives byte-identical output. Verified on Python 3.14.7: two runs produced identical manifests, and the unit tests compare the files byte for byte. Other Python versions are not tested.

## Record format (`notes.jsonl`, one JSON object per line)

| Field | Meaning |
|---|---|
| `note_id` | `N0001`... |
| `patient_id` | `P0001`...; the same patient appears in 4 notes |
| `note_type` | `history_and_physical`, `progress_note`, `discharge_summary`, `radiology_report`, `telephone_encounter` |
| `note_date` | ISO date of the note |
| `text` | note text |
| `spans` | list of labeled spans, sorted, non-overlapping |

Each span has `start`/`end` (character offsets into `text`, end exclusive), `type`, `subtype`, `entity`, `text`, and, for dates only, `norm` (the true ISO date).

- **Types:** `NAME`, `DATE`, `ID`, `PHONE`, `EMAIL`, `ADDRESS`.
- **Entity:** one id per real-world person across all of a patient's notes (`P0007` patient, `P0007:spouse`, `P0007:kin`, `D01`... providers). Use it to test consistent pseudonyms. Identifier spans that belong to a patient carry the patient id.
- **Timeline:** each patient has one prior date, admission, discharge and follow-up date. `DATE` spans of the same subtype in different notes have the same `norm`, so shifted outputs can be checked for preserved intervals.

## Labeling conventions

- Label the value only. "Dr. Kim" labels `Kim`; "MRN: 1234567" labels `1234567`; credentials such as ", MD" are not labeled.
- "Last, First M" and "First M Last" are each one `NAME` span.
- Dates are labeled in every format, including forms with no year (`Apr 21`, `4/21`).
- A bare town ("Lindenfield, IA") is an `ADDRESS` span with subtype `TOWN`.
- Unlabeled on purpose, to test false positives: blood pressures (`BP 132/84`), dose ratios (`5/325 mg`), pain scores (`7/10`), lab values, ICD-10-style codes, room numbers, eponyms (`Wilson disease`, `Bell`...) and ages under 90.

## What the tests check

Determinism; every span's offsets match its text and none overlap; at least 500 notes with all six types present; date `norm` values are ISO and consistent per patient; patient name spans carry the patient entity id; no labeled value (phone, ID, name...) appears elsewhere in a note unlabeled, apart from eponym uses; every phone-like string is in the fictional 555-01xx block.

## Known limitations (read before trusting any score)

- **Template-based text.** Five note layouts and eight diagnoses. Real notes are messier (abbreviations, typos, free-form dictation, copy-paste). Scores here will not predict real-world performance.
- **Easy formats.** Every phone is `555-01xx`, every SSN starts with 9, and every email ends in `example.com` or `example.org`. A regex can find these more easily than real ones, so recall on PHONE, EMAIL and SSN will look better than it would in practice. Results must say so.
- **Small name pools.** About 60 first names and 60 surnames, so a model could partly memorize them. A few surnames double as words or eponyms on purpose.
- **Coverage gaps.** Not all HIPAA Safe Harbor categories are present. There are no facility or organization names, URLs, device or vehicle identifiers, and no ages of 90 or over.
- **Clinical realism not reviewed.** Content was written to look plausible, not checked by a clinician. For example, a consulting provider's specialty is not matched to the diagnosis.
- **Not frozen.** Treat the numbers above as a snapshot of seed 20261027 at generator version 0.1.
